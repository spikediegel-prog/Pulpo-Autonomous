# Pulpo Autonomous v0.3.0 — Bounded Routing and Trustworthy JSON

This release puts two priorities at the front of Pulpo Autonomous: predictable
command intake and verifiable, bounded JSON data. The new opt-in command router
joins the deterministic JSON audit/evidence and bounded parsing foundations
already shipped in v0.2.0. Authority continues to belong to the existing
governance path; transport readiness and well-formed JSON never grant permission.

## Headline: bounded command traffic routing

The router now integrates at the existing `ExecutionTracker.execute()` boundary
([PR #19](https://github.com/spikediegel-prog/Pulpo-Autonomous/pull/19)). It adds:

- bounded item counts, queued bytes, command size and transport TTL;
- immediate rejection under contention rather than unbounded transport waiting;
- terminal DROP/REJECT outcomes for expired, malformed, overloaded, faulty or
  substituted traffic;
- byte-identity checks before the original owner continues with unchanged arguments;
- restart/replay behavior that preserves UNKNOWN and never invents retry authority.

Physical-command intake stays FIFO, batch size one, with priority and deduplication
off. Safety fallback and observation recording stay outside transport intake.
Original boot, lease, action, expiry, offline-window, command-budget and
reconciliation checks remain in the existing command owner. No new executor,
ledger, canonical writer or authority plane is introduced.

The router is **opt-in**. It reuses the existing standalone `sentry-traffic`
package; this release does not publish or bundle that package. Default callers
need no dependency. See [setup and scope](../AUTONOMOUS_TRAFFIC_ROUTER.md).

## Headline: JSON that can be trusted within its bounds

Both sides of the JSON work matter:

**Deterministic audit and evidence.** Canonical JSON serialization, hash-chained
journal records, canonical audit/delta roots and integrity checks provide
repeatable records whose changes can be detected. Existing indexed/filtered
reads and verified-integrity reuse reduce unnecessary audit materialization;
external SQLite mutation forces revalidation. These foundations carry forward
from v0.2.0 and remain part of the same authoritative audit path.

**Bounded input and parsing.** Request, provider and evidence surfaces have
explicit byte, nesting-depth, item-count and string-size limits on the tested
paths. Oversized or structurally excessive JSON is rejected rather than treated
as unbounded governance input. This release adds HTTP probing hardening
([PR #9](https://github.com/spikediegel-prog/Pulpo-Autonomous/pull/9)), including
request-target/header limits and malformed request-admission checks before
routing. JSON validity alone is never authority, provenance or execution success.

Together, these are the release's lead improvements to data handling: bounded
intake, consistent records and fail-closed verification. They are not a claim
of measured autonomous-system throughput or universal input containment.

## Also included since v0.2.0

- Explicit documentation of host-bound versus Pulpo-bound capabilities ([PR #17](https://github.com/spikediegel-prog/Pulpo-Autonomous/pull/17)).
- Safer public repository defaults and refreshed constitutional mutation anchors.
- An optional GPU audit-hash benchmark ([PR #16](https://github.com/spikediegel-prog/Pulpo-Autonomous/pull/16)); canonical verification remains CPU-authoritative. Prior GPU results were near parity, not a demonstrated speedup.
- Python package metadata aligned with the v0.3.0 release version.

## Validation and testing invitation

Verified on the merged router source: 31 focused tests passed on Windows Python
3.12.10 and WSL Python 3.14.4. Full WSL discovery passed 429 tests with one
historical-proof skip because the required commits are absent from this fork.
The focused tests cover unchanged journal bytes/governed hashes, queue budgets,
contention, TTL, malformed/Unicode input, byte substitution, boot/reconciliation
vetoes, fallback/observation availability, UNKNOWN, restart, replay and tamper.
Release preparation changes documentation and version metadata only.

If you have an appropriate test environment, take the simulated router proof for
a spin and share the results, OS/Python/router versions and exact command:

```powershell
python -W error scripts\test_command_router.py --router-source C:\Users\spike\SENTRY
```

Use your own installed package or explicit source location. The focused runner
fails if the router is unavailable or enabled-path tests skip. Ordinary root
CI without that optional package verifies default-off behavior and skips the
enabled integration; it does not prove the enabled path.

## Evidence boundaries

**Verified:** transport bounds and preserved command/journal invariants in the
tested simulated path. **Recorded:** carried-forward JSON/audit foundations and
prior upstream benchmarks. **Unknown:** autonomous hardware latency, CPU/memory
or throughput gains, multiwriter journal safety, fleet scale, production
containment and historical transfer of earlier Pulpo performance improvements.
Existing broader Python 3.14 SQLite finalization warnings remain outside this
router's JSONL path. This release does not claim repository-wide warning cleanup.

No real mission, device adapter or external provider was started for release
validation. The physical layer remains a modeled offline command path, not a
newly proved live kernel-to-hardware bridge. Hardware trials must retain the
existing authorized host and safety interfaces.
